## Key Concepts

| Concept | Meaning | Read |
|---------|---------|------|
| **SHADOW Pseudonym** | Persistent identifier used within SHADOW (e.g., "Zenith") | Part IV |
| **Project Sovereignty** | Team Leader has operational authority within their project | Parts II, V |
| **Commons** | Minimal central layer providing infrastructure + arbitration (NOT command) | Part I, II |
| **Team Leader** | Person who originates a project and leads it | Part V |
| **Arbitration** | Neutral dispute resolution when direct negotiation fails | Part III |
| **Member Assembly** | All members voting on major decisions (Stage 3+) | Parts II, III |
| **Stage** | Growth milestone (Stage 1: 5–15 → Stage 5: 10,000+ members) | Parts II, XI |

## Critical Design Achievements

✅ **Anonymity + Credibility** — Pseudonyms internally; verifiable portfolios using pseudonym  
✅ **Decentralisation + Revenue** — Zero automatic cuts; optional revenue-share for Commons support  
✅ **Autonomy + Coordination** — Team Leaders sovereign; explicit decision matrix  
✅ **Resilience Against Failure** — Succession planning; distributed infrastructure; project independence  
✅ **Scalability Without Hierarchy** — Evolving governance; no permanent central authority
